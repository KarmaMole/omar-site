# omarkamel.com audit, 2026-10-02

Read-only audit. No code was changed.

**What this is:** Omar's public portfolio and brand site (Next.js 15 + Payload CMS 3.81 on Neon Postgres + Vercel Blob, hosted on Vercel). One admin user.

**Bar applied:** a production public site that represents Omar professionally to clients. Copy, visual polish, SEO, performance and accessibility carry a lot of weight. Enterprise concerns (scale, multi-user permissions, heavy test suites) carry little.

**How it was checked:**
- Four parallel code reviews: backend/security, performance/tooling, SEO, frontend/accessibility.
- My own pass through the live site's copy.
- Full-page screenshots of 10 pages at 1440px and 390px, taken with headless Edge (the Chrome window was in the background).
- Read-only live checks with curl.
- Tool runs: `tsc`, `lint`, `npm audit`, `npm outdated`, `next build`.

**Tooling results (real output):**
- `tsc --noEmit`: clean.
- `npm run lint`: 1 warning (unused `categories` variable in `app/(site)/dispatch/[slug]/page.tsx:71`).
- `next build`: passes, 109 static pages.
- Tests: none. CI: none.
- `npm audit --omit=dev`: 34 advisories (1 critical in `next`, 15 high, 17 moderate, 1 low).

**Skipped:**
- `node_modules`, `.next` and lockfiles.
- `docs/superpowers` (grepped only).
- CMS body content beyond what is visible on the pages I fetched.
- Lighthouse and real-user metrics weren't run, so every performance note is theoretical unless marked measured.

## High

**1. Hidden Work items are publicly readable via the API and by URL**
- Category: security / privacy.
- Refs: `collections/Work.ts:41`, `collections/Projects.ts:45` (`read: () => true`); `lib/payload/queries.ts:113-126, 196-209` (`getWorkBySlug` and `getProjectBySlug` don't filter `hidden`).
- Verified live: `GET https://omarkamel.com/api/work?where[hidden][equals]=true` returns 7 hidden items: Core42, e&, FAB, ADCB, GMC and Saudia placeholder entries, plus "Progress". Hidden items also render at `/work/<slug>` without `noindex`.
- Why it matters: "hidden" promises not-public, but the client placeholders are readable by anyone.
- Fix: collection read access becomes `user ? true : { hidden: { not_equals: true } }`, and the by-slug queries add the same filter so those pages 404.
- Effort: S.
- Risk: low. You can no longer preview a hidden item by its URL (the admin still sees everything).

**2. Dispatch tag and category filtering is broken (my regression)**
- Category: correctness.
- Ref: `lib/payload/queries.ts:253-262`. The `select` I added in commit `fdf8faa` omits `categories` and `tags`.
- Effect: category pills never render, and every tag link on a post (for example `/dispatch?tag=Claude`) shows "No posts found".
- Fix: add `categories: true, tags: true` to that select.
- Effort: S. Risk: none.

**3. /work, /studio and /dispatch send an empty page before JavaScript runs**
- Category: correctness / SEO / performance.
- Refs: `work/page.tsx:53-56`, `studio/page.tsx`, `dispatch/page.tsx`, plus `useSearchParams` in the `*-content.tsx` files and `category-filter.tsx`.
- Verified live: the `/work` HTML has 0 `<h1>` elements and 0 work links. Next bails out to client-side rendering.
- Why it matters: your three main portfolio indexes are blank to non-JS crawlers, AI search tools and link unfurlers, and their LCP waits on JavaScript.
- Fix: render the full unfiltered grid on the server and apply the filter on the client. Alternatively, pass `searchParams` in from the page.
- Effort: M. Risk: medium (touches the filter UX on three pages).

**4. Homepage video cards can't be clicked through to the project**
- Category: UX / correctness.
- Refs: `components/hero-card-video.tsx:32-50` (a full-card `absolute inset-0 z-20` play button), used at `app/(site)/page.tsx` for the Featured Work and Studio heroes.
- Effect: clicking anywhere on the card, including the title, plays the video. Nothing leads to `/work/storm-ai-short`.
- Fix: shrink the button to a centred play control and keep the rest of the card as the link. Label it "Play video: {title}".
- Effort: S. Risk: low.

**5. Schema changes are pushed straight to the production database, with no migrations and no undo**
- Category: data integrity.
- Refs: `payload.config.ts:51-55` (no `push: false` or migrations); no `migrations/` folder; no `versions` on any collection.
- Why it matters: `.env.local` points at the production Neon database. Any `next dev` run auto-pushes schema. A renamed or removed field would drop production columns with no review step. Separately, an accidental overwrite or delete of a post is unrecoverable except via Neon point-in-time restore. Today I avoided this with a dry run first, but that's process, not a safeguard.
- Fix:
  - Point local dev at a Neon branch.
  - Set `push: false` in production config and adopt `payload migrate`.
  - Enable `versions: { maxPerDoc: 10 }` on Work, Projects and Dispatches for undo.
- Effort: M.
- Risk: medium. Needs a one-off baseline migration and new version tables.

**6. Security patch backlog, including Next.js**
- Category: dependencies.
- Details: `next` 15.4.11 → 15.5.x (critical advisory); Payload 3.81 → 3.90 (all `@payloadcms/*`); `sanitize-html` (two bypasses); `sharp`; `nodemailer`.
- Severity is theoretical for a mostly static, admin-authored site, but the backlog is growing.
- Fix: upgrade in batches with a build after each: Next first, then the Payload family (check the admin and importMap), then the rest.
- Effort: M.
- Risk: medium for Payload, low for the others.

## Medium

**7. Missing pages: soft 404s and an unbranded 404**
- Category: correctness / brand / SEO.
- Verified live: `/work/does-not-exist` returns **200** with the homepage title (the site-wide `loading.tsx` starts streaming before `notFound()` runs). Unknown top-level URLs like `/nope` show Next's plain white "404" page with no nav.
- Fix:
  - Call `notFound()` in `generateMetadata` too, or narrow `loading.tsx`.
  - Add `app/(site)/[...missing]/page.tsx` so the branded 404 renders.
- Effort: S. Risk: low (make sure `/admin` and `/api` aren't shadowed).

**8. Undeclared dependency `@dnd-kit/modifiers`**
- Category: dependencies.
- Ref: `components/admin/reorder-list.tsx:20`.
- Why it matters: it only resolves because npm hoists it. This is the same class of failure as the earlier `@payloadcms/ui` build break.
- Fix: `npm install @dnd-kit/modifiers`.
- Effort: S. Risk: none.

**9. Contact form can fail silently or misleadingly**
- Category: correctness / security.
- Refs: `app/api/contact/route.ts:56-121`, `lib/mailer.ts`, `components/contact-form.tsx:68-79`.
- Problems:
  - If SMTP env vars are missing in production, the route logs the visitor's message to Vercel logs and returns success. The visitor sees "sent" and you get nothing.
  - No SMTP timeouts.
  - Any non-JSON error (500, 413) shows the visitor "Network error".
  - No length caps on fields.
  - The email check accepts `a@b.c,x@y.z`.
- Fix:
  - Return 500 in production when SMTP isn't configured.
  - Add 10-second SMTP timeouts.
  - Parse responses defensively.
  - Cap name, email and message lengths, and reject `,<>;` in email.
- Effort: S. Risk: low.

**10. Contrast fails WCAG AA on readable text**
- Category: accessibility.
- Problem spots:
  - Contact form labels are 2.7:1 (`contact-form.tsx:138,161,184`).
  - Small mono text at `light-300/70` is about 4.3:1: client names, transmission tags, share label, services references.
  - Hero "Scroll" and the lightbox counter are 3.4:1.
  - Cookie banner text is 3.6:1.
- Full-opacity `light-300` (7.9:1) and cyan are fine.
- Fix: use full `light-300` for anything people must read, or add one dimmer token around `#8a8a8a` (5.6:1) instead of opacity suffixes.
- Effort: S. Risk: visual change, so it needs your OK (the typography rule).

**11. Media edits never refresh the site cache**
- Category: correctness.
- Ref: `collections/Media.ts` has no hooks.
- Effect: replacing an image, editing alt text or deleting media leaves stale or broken images for up to an hour.
- Fix: add `afterChange` and `afterDelete` hooks that revalidate work, studio, dispatch, settings, clients and homepage.
- Effort: S. Risk: none.

**12. Hero and above-the-fold content stay invisible until JavaScript runs**
- Category: performance / resilience.
- Refs: `components/hero-animations.tsx:31,54`, `components/fade-in.tsx:39,68`.
- Effect: the server HTML ships the hero `<h1>` and the priority images at `opacity:0`. This likely delays LCP, and visitors without JS see blank sections (theoretical, not measured).
- Fix: switch to a CSS-only fade-up so content is visible on arrival, or skip the animation above the fold.
- Effort: S-M. Risk: low (subtle visual change).

**13. Keyboard and screen-reader gaps in interactive pieces**
- Category: accessibility.
- Problems:
  - The lightbox has no focus trap and doesn't return focus on close (`gallery-lightbox.tsx`).
  - The mobile menu has no `aria-expanded`, its close button isn't reachable by Tab, and the page behind it still scrolls (`nav.tsx`).
  - `/play` swallows every key including Tab, and the CV can only be reached by winning the game, even though the PDF is public at a direct URL (`tron-game.tsx:600-606, 882-888`).
- Fix: add the focus handling and ARIA attributes. On `/play`, start only on Space, Enter or the arrow keys, and add a quiet "skip the game, download CV" link.
- Effort: S. Risk: none.

**14. Custom cursor costs accessibility and CPU**
- Category: accessibility / performance.
- Ref: `components/custom-cursor.tsx`.
- Problems: it hides the native cursor everywhere, including the text caret in form fields. It ignores reduced-motion. It runs an animation loop forever and re-binds listeners on every DOM change.
- Fix: keep the native cursor on inputs, respect `prefers-reduced-motion`, use one delegated listener, and stop the loop when idle.
- Effort: M. Risk: low. Whether to keep the cursor at all is your call.

**15. The AI dispatch generator writes off-voice copy, and the route is fragile**
- Category: writing / correctness.
- Ref: `app/(site)/api/generate-dispatch-meta/route.ts:40-60`.
- Copy problems: the prompt has no em-dash rule and no voice rule. The live excerpts it produced contain em-dashes ("isn't just time—it's...") and third-person phrasing in your own blog ("Omar's Claude editor Pax... lets the creator focus").
- Robustness problems:
  - No `maxDuration` setting.
  - No error handling around the Claude call, the fal.ai call or the image download.
  - Each run leaves an orphan media file.
  - Hallucinated categories aren't filtered out.
- Fix:
  - Add "no em-dashes, first person, Omar's voice" to the system prompt.
  - Set `maxDuration = 300`.
  - Wrap each step in error handling and check `imageResponse.ok`.
  - Filter categories to the allowed list.
- Effort: S. Risk: low.

**16. Live dispatch copy needs a pass**
- Category: writing.
- Problems:
  - Two homepage excerpts contain em-dashes.
  - One excerpt is in the third person.
  - One meta description is cut off mid-sentence ("...sustainable AI").
  - One older post has a second `<h1>` inside its body (`/dispatch/the-tools-that-earned-their-place`).
- Fix: edit the copy in the CMS. I can draft replacements for you to approve.
- Effort: S. Risk: none.

**17. SEO plumbing: relative URLs and a lost feed link**
- Category: SEO.
- Problems:
  - JSON-LD `image` values are relative on every detail page and on /about. Google expects absolute URLs.
  - RSS enclosures are relative, typed `image/jpeg` for `.webp` files, with `length="0"` (`app/feed.xml/route.ts:30`).
  - Pages that set their own `alternates` drop the RSS autodiscovery link, so it appears nowhere.
- Fix: add an `absUrl()` helper, derive the enclosure MIME type, and re-add the feed link on the home and dispatch pages.
- Effort: S. Risk: low.

**18. Large uploads will fail in production**
- Category: data integrity.
- Refs: `collections/Media.ts:12` (accepts video), `payload.config.ts:59-65` (Blob plugin without `clientUploads`).
- Effect: Vercel caps function request bodies at about 4.5 MB, so large images and almost any video fail with an opaque error.
- Fix: set `clientUploads: true`, and drop `video/*` if you don't upload video.
- Effort: S. Risk: low (verify the Blob token supports client uploads).

**19. The reorder tool can leave a half-applied order**
- Category: data integrity.
- Ref: `app/api/reorder/route.ts`.
- Problems:
  - It runs N sequential updates with no transaction, so a mid-way failure scrambles `/work`.
  - Bad JSON returns an unhandled 500.
  - The page silently shows only the first 100 items (`getAllWork` limit).
- Fix: use one Payload transaction, move the JSON parse inside the error handler, and raise or remove the limit.
- Effort: S-M. Risk: low.

**20. Filters and categories drift from the CMS**
- Category: correctness / architecture.
- Problems:
  - Category lists are hardcoded three times, separately from the CMS options, so a new category gets no filter pill.
  - Active-pill matching is case-sensitive while filtering is not: `?category=commercial` highlights nothing.
- Fix: one shared category module used by both the collections and the filters, with a single case-normalising helper.
- Effort: S. Risk: low.

**21. Some video links won't play**
- Category: correctness.
- Refs: `hero-card-video.tsx:6-19`, `media-embed.tsx`, `parse-embeds.ts`, `resolve-vimeo.ts`.
- Problems:
  - YouTube Shorts, `/embed/` and `/live/` URLs produce an empty video ID.
  - Unlisted Vimeo links lose their privacy hash, so the video won't play.
  - The two parsers disagree with each other.
  - Every iframe has the generic title "youtube embed".
- Fix: one tested `toEmbedUrl()` helper that keeps the Vimeo `?h=` hash, and the item title on each iframe.
- Effort: S-M. Risk: low.

**22. Analytics probably under-reports**
- Category: correctness.
- Ref: `next.config.mjs:21-33`.
- Problem: CSP `connect-src` only allows `www.google-analytics.com`. GA4 commonly sends hits to `region1.google-analytics.com` and `*.analytics.google.com`, which would be silently blocked.
- Fix: add those hosts.
- Effort: S. Risk: low. Verify in the console after accepting cookies.

## What's well built

- **Rendering and caching:** every public route is static or ISR. Two-layer caching with tag invalidation is wired consistently (except Media, see 11). Payload `select` clauses on list queries. AVIF.
- **Security basics:** a real CSP and HSTS. Auth on every admin API route and on the new homepage server action. JSON-LD is escaped. `sanitize-html` is used on the rich-text fallback. No real secrets in the repo.
- **SEO groundwork:** explicit absolute canonicals on every route. Open Graph images on every route. The `openGraph` object-replacement gotcha is handled everywhere. A title template. Breadcrumb and CreativeWork/Article schema. The sitemap excludes hidden items. Trailing slashes are normalised.
- **Accessibility groundwork:** skip link, `lang`, global `:focus-visible`, a reduced-motion override in CSS, `inert` on the closed mobile menu, and keyboard and swipe support in the lightbox.
- **Heavy code stays where it belongs:** the Tron game and AI SDKs stay out of shared bundles, and the lightbox is lazy-loaded. Measured shared JS is about 101 kB.
- **Visual design:** strong and consistent. Clear hierarchy, a restrained palette, and good card treatment at both widths. The detail pages read well. The About page copy has a distinct, confident voice.
